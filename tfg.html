01

Contexto y alcanceContext & scope

Durante mis prácticas en Datatronics, dando soporte a redes 5G en producción, vi de primera mano cómo las telecomunicaciones están adoptando paradigmas cloud-native. Quise entender a fondo qué implica desplegar una red móvil sobre una plataforma de orquestación de contenedores, y de ahí salió este TFG.

El objetivo: diseñar, desplegar y documentar una red 5G SA funcionalmente completa —núcleo y acceso radio— sobre un clúster de Kubernetes de un único nodo, con componentes de código abierto de OpenAirInterface distribuidos con Helm. Como no había hardware SDR disponible (y un USRP es caro y exigía acceso al nodo físico), el enlace radio se sustituye por rfsimulator, que mantiene intacta toda la pila de protocolos por encima.

During my internship at Datatronics, supporting production 5G networks, I saw first-hand how telecoms is moving to cloud-native paradigms. I wanted to deeply understand what it takes to run a mobile network on a container orchestration platform, and that became this thesis.

The goal: design, deploy and document a functionally complete 5G SA network —core and radio access— on a single-node Kubernetes cluster, using OpenAirInterface open-source components packaged with Helm. With no SDR hardware available (a USRP is expensive and needed physical node access), the radio link is replaced by rfsimulator, which keeps the whole protocol stack above it untouched.

02

ArquitecturaArchitecture

Siguiendo el modelo de referencia del 3GPP, cada plano de comunicación tiene su propia interfaz: el SBI (HTTP/2) circula por la red por defecto del clúster, mientras que N2, N3, N4 y N6 se crean como interfaces macvlan independientes mediante NetworkAttachmentDefinition de Multus con IP estática. Following the 3GPP reference model, each communication plane gets its own interface: the SBI (HTTP/2) runs over the cluster's default network, while N2, N3, N4 and N6 are separate macvlan interfaces created from Multus NetworkAttachmentDefinitions with static IPs.

Incidencias resueltasProblems solved

La parte más valiosa del trabajo: muchos de estos fallos eran silenciosos. Los fui resolviendo capa a capa, verificando cada interfaz y cada socket antes de subir al siguiente nivel de la pila. The most valuable part of the work: many of these failures were silent. I worked through them layer by layer, checking each interface and socket before moving up the stack.

La más laboriosaThe hardest one

Saturación del buffer del socket rfsimulatorrfsimulator socket buffer saturation

SíntomaSymptom

El gNB registraba en bucle write() failed, errno(11) (EAGAIN). Las estadísticas radio no mostraban errores, pero el plano de usuario no funcionaba y el SRB1 se quedaba congelado con un contador de bytes constante.

The gNB kept logging write() failed, errno(11) (EAGAIN). Radio stats showed no errors, yet the user plane was dead and SRB1 froze at a constant byte count.

DiagnósticoDiagnosis

Esa contradicción era la pista: la banda base decodificaba bien lo que llegaba, pero llegaban menos muestras de las necesarias. El fallo no estaba en la capa física, sino en el transporte TCP que sustituye al enlace aéreo: el jitter del hipervisor sobre vCPUs compartidas saturaba el buffer de envío del kernel. Sin acceso al nodo Proxmox no había CPU pinning posible.

That contradiction was the clue: baseband decoded everything it received, but fewer samples than needed were arriving. The fault wasn't in the PHY but in the TCP transport replacing the air link: hypervisor jitter on shared vCPUs was filling the kernel send buffer. With no access to the Proxmox node, CPU pinning was off the table.

Probado sin éxito: menos hilos (parallel_config), muestreo a 3/4 (-E) y menos ancho de banda.

Tried without success: fewer threads (parallel_config), 3/4 sampling (-E) and a narrower carrier.

SoluciónFix

Ampliar los buffers de socket del kernel (de 212 kB por defecto a 64 MB máx. / 16 MB inicial), en la VM y dentro del contenedor de Minikube. El jitter sigue existiendo, pero ya no se traduce en pérdida de muestras.

Enlarge the kernel socket buffers (from the 212 kB default to 64 MB max / 16 MB default), both on the VM and inside the Minikube container. Jitter still exists, but no longer turns into lost samples.

# Debian VM + Minikube
echo 67108864 > /proc/sys/net/core/wmem_max
echo 67108864 > /proc/sys/net/core/rmem_max
echo 16777216 > /proc/sys/net/core/wmem_default
echo 16777216 > /proc/sys/net/core/rmem_default

Complementado con kernel RT y intel_pstate=disable processor.max_cstate=1 idle=poll en GRUB.

Backed up by an RT kernel and intel_pstate=disable processor.max_cstate=1 idle=poll in GRUB.

  1. 01

    IPs estáticas duplicadas en los NADDuplicate static IPs in the NADs

    Síntoma: la interfaz N2 nunca aparecía en el Pod del gNB, sin ningún error de Multus. Causa: oai-amf-n2 y oai-gnb-n2 venían con la misma IP. Solución: verificar la unicidad de IPs de cada NAD y reasignarlas en el values.yaml.

    Symptom: the N2 interface never showed up in the gNB pod, with no Multus error. Cause: oai-amf-n2 and oai-gnb-n2 shipped with the same IP. Fix: check IP uniqueness across NADs and reassign them in values.yaml.

  2. 02

    Socket SCTP del AMF en la interfaz equivocadaAMF SCTP socket on the wrong interface

    Síntoma: la asociación SCTP gNB–AMF no se establecía. Diagnóstico: /proc/net/sctp/eps mostraba el AMF escuchando en eth0, porque OAI enlaza a la primera interfaz disponible. Solución: fijar interface_name: n2 (puerto 38412) en el config.yaml del AMF.

    Symptom: the gNB–AMF SCTP association never came up. Diagnosis: /proc/net/sctp/eps showed the AMF listening on eth0, since OAI binds to the first available interface. Fix: set interface_name: n2 (port 38412) in the AMF's config.yaml.

  3. 03

    El gNB apuntaba al ClusterIP del AMFgNB pointed at the AMF's ClusterIP

    Causa: el gNB usaba la IP del Service de Kubernetes, pero N2 es un plano aislado con Multus que no pasa por el Service. Solución: apuntar amfhost a la IP macvlan N2 del AMF. Tras esto, el registro NGAP se completó.

    Cause: the gNB used the Kubernetes Service IP, but N2 is an isolated Multus plane that doesn't go through the Service. Fix: point amfhost at the AMF's N2 macvlan IP. NGAP registration then completed.

  4. 04

    rfsimulator: dos clientes, ningún servidorrfsimulator: two clients, no server

    Causa: gNB y UE arrancaban en modo cliente, así que la conexión no llegaba a producirse, sin dar error. Solución: serveraddr = "server" en el gNB y rfSimServer del UE apuntando a la IP del gNB. Verificado con st = 01 en /proc/net/tcp.

    Cause: both gNB and UE started as clients, so the connection silently never happened. Fix: serveraddr = "server" on the gNB and the UE's rfSimServer pointing at the gNB IP. Verified via st = 01 in /proc/net/tcp.

  5. 05

    PCF ausente en el establecimiento de la sesión PDUMissing PCF during PDU session setup

    Síntoma: PCF SM Policy Association Creation was not successful. Solución: en lugar de desplegar una PCF innecesaria para el alcance, activar use_local_pcc_rules: yes en el SMF.

    Symptom: PCF SM Policy Association Creation was not successful. Fix: rather than deploying a PCF that was out of scope, enable use_local_pcc_rules: yes on the SMF.

  6. 06

    Orden de arranque y reconexiónStartup order and reconnection

    Causa: el nr-UE no reconstruye la conexión si el gNB se reinicia, y Kubernetes no garantiza orden entre Deployments. Solución: procedimiento fijo: MySQL → UDR/NRF → resto del 5GC → gNB → nr-UE, reiniciando en ese orden.

    Cause: the nr-UE won't rebuild its link if the gNB restarts, and Kubernetes doesn't order Deployments. Fix: a fixed procedure: MySQL → UDR/NRF → rest of 5GC → gNB → nr-UE, restarting in that order.

Metodología de depuraciónDebugging approach

  • Por capas: interfaz → socket → asociación → registro, sin avanzar hasta validar la capa anterior. Los logs suelen indicar el último protocolo en el que se quedó la pila.
  • Layer by layer: interface → socket → association → registration, never moving on until the layer below is validated. Logs usually point to the last protocol the stack reached.
  • Inspección de bajo nivel vía /proc/net/sctp/eps y /proc/net/tcp, porque las imágenes de OAI apenas traen herramientas de red.
  • Low-level inspection through /proc/net/sctp/eps and /proc/net/tcp, since OAI images ship with barely any network tools.
  • ps aux para ver los argumentos reales de arranque: useAdditionalOptions sobrescribe los ficheros de configuración y podía ocultar la causa real.
  • ps aux to see the real startup arguments: useAdditionalOptions overrides the config files and could hide the real cause.
  • Revisar los ConfigMaps generados por Helm: un error de indentación puede dar un YAML válido pero funcionalmente incorrecto.
  • Review the ConfigMaps Helm renders: an indentation mistake can produce valid but functionally wrong YAML.

ResultadosResults

El nr-UE completa la sincronización (PSS/SSS, MIB), la conexión RRC, el registro NAS con 5G-AKA y el establecimiento de la sesión PDU, recibe la IP 12.1.1.100 en oaitun_ue1 y cursa tráfico por la cadena completa radio → GTP-U → N3 → UPF → N6. The nr-UE completes sync (PSS/SSS, MIB), the RRC connection, NAS registration with 5G-AKA and PDU session establishment, gets 12.1.1.100 on oaitun_ue1 and carries traffic through the whole radio → GTP-U → N3 → UPF → N6 chain.
